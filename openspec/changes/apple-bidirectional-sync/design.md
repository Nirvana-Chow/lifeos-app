# Design

## Context

The existing personal and calendar services already own record validation, revision CAS, command receipts and history. Their PostgreSQL repositories commit independently; personal runtime currently returns before optional calendar initialization. Apple import evidence is immutable and is not a dynamic synchronization baseline. Current CLI exports omit some native fields and cannot safely provide a complete recurrence/alarm round trip.

The owner has approved this scheme and requested implementation and eventual website publication. This design refines implementation details within that approved scheme. It does not grant a device identity, activate a background task, migrate live data or alter production trust. Existing UI qualification and unfinished tasks remain independent.

## Goals / Non-Goals

**Goals:** canonical LifeOS business records, one fenced Mac executor, loss-aware observations, durable reconciliation, same-transaction business/outbox/state, explicit conflicts and deletion candidates, authenticated default-closed candidate APIs, manual synthetic preview and recoverable execution.

**Non-Goals:** inventing totals or native capabilities; turning missing fields into null; rewriting authentication; using browser cookies as a Mac identity; a second business database/writer; silently replacing cancellation with deletion; installing a daemon, upgrading CLI tools, accessing real records or granting live schema privileges from source/startup.

## Decisions

1. **Keep the existing business writer.** Sync incoming patches call PersonalService/CalendarService using transaction-bound versions of their existing repositories. Optional capture hooks append immutable outbox rows after history and before COMMIT. Sync state, command receipt and business mutation share that same connection/transaction; a hook failure rolls back the whole operation. Defaults remain byte-compatible with repositories constructed without capture.
2. **Separate observations from authority.** Known values, explicit known null and unavailable observations are distinct. Native snapshots retain raw dates/time zones, recurrence selectors, complete alarms, identity/aliases and opaque evidence. Existing business fields are projected through a narrow adapter; an incoming change to a field the business model cannot represent is blocked and preserved, not written into an unofficial second canonical store. Full native-field adoption remains an explicit tracked item.
3. **Use deterministic three-way merge.** Compare each atomic field against the last mutually acknowledged base. One-sided changes propagate; independent changes combine; same-field, unknown-field, identity and terminal-state conflicts retain both values. Arrays such as recurrence and alarms are atomic to avoid invalid mixtures. Do not use device timestamps as last-write-wins. Echo suppression requires matching operation identity, expected revision and semantic hash; a phone-side edit is not discarded merely because a marker matches.
4. **Fence both execution and acknowledgement.** Owner/space/bridge bindings and monotonically increasing lease fences gate protocol operations. Read-only pull returns notifications/status, never executable commands. Write-authorized prepare persists a complete immutable delivery from current canonical state; claim and fresh exact-claim authorization separately gate native save. An expired executor cannot advance state or revive an old claim. Automatic bridge/identityEpoch handover is closed in this source phase. Before any native write, persist intent, claim request/receipt and expected native hash/store epoch under the original shared writer-fence verifier.
5. **Make unknown outcomes recoverable.** Persist prepared/claimed/native-applying/readback/receipt/ack states with atomic file+directory fsync. A timed-out create is resolved using the same immutable identity and fresh readback, never blindly recreated. Lost replies reuse the exact command and payload, including a server receipt durably saved before ACK. Only never-claimed issued attempts may be retired by exact CAS; claimed uncertainty stays blocked/unknown. Advance base/cursor only after native readback and server acknowledgement, and never delete pending intent to make progress.
6. **Require complete coverage before a tombstone candidate.** Match store epoch, account/container scope and coverage, exclude truncation/permission loss/window movement/ID ambiguity, and require native resolution. Missing records produce candidates for confirmation, not automatic completion, cancellation, permanent deletion or recreation. A bounded calendar window is not a complete calendar deletion scan.
7. **Use a capability contract rather than lossy CLI assumptions.** The adapter reports full-snapshot, writable-field, recurrence-scope and alarm preservation support. The current CLI adapter reports its verified limitations and rejects unsafe writes, including old due/alarm behavior. Synthetic adapters exercise the full protocol. A narrow native EventKit adapter must later prove complete snapshot/patch/readback support; unsupported native invitation or event cancellation operations remain explicit.
8. **Keep API authentication separate from synchronization.** HTTP receives a trusted principal reader, validates owner/space/bridge/scopes and does not accept identity from JSON or arbitrary headers. An absent approved device provider fails closed. Better Auth's existing verified owner/MFA session may support manual owner preview; it is not a device write identity. Device authorization should reuse mature native/OAuth mechanisms in its own controlled phase, not custom crypto or copied cookies.
9. **Expose protocol operations, not arbitrary execution.** Candidate operations are capabilities, preview, lease, read-only pull/status, observation, prepare, claim, fresh claim authorization, never-claimed retirement, receipt/readback and ACK. Delivery writes require a current lease and an independent business permit. Lease acquisition has its own authorization/binding gate rather than circularly requiring an existing lease. Bodies are strict and bounded; responses private/no-store; errors expose stable codes rather than records, credentials or paths. A Skill describes operations; the API enforces them.
10. **Use the same source and qualified delivery.** All code stays in this application repository. Runtime state, credentials and mappings stay outside Git. Proposed SQL is additive, owner RLS/FORCE RLS, restricted runtime roles, no source/history overwrite, no blanket UPDATE/DELETE/TRUNCATE. Readiness is read-only. Source, synthetic integration, native capability, real two-way phone readback, website release and owner acceptance have separate evidence.

## Risks / Trade-offs

- Current business models cannot represent every Apple field: retain raw evidence and fail closed for unsupported changes while keeping full-field work open.
- EventKit lacks a server CAS and durable per-record cursor: re-read full authorized coverage and use semantic fingerprints; do not claim iPhone concurrency is locked by the Mac.
- Calendar native cancellation is read-only and recurrence scopes differ from Reminders: preserve terminal/series/occurrence semantics and report unsupported operations.
- A source-only candidate cannot prove actual device authorization or native delivery: keep those gates visible rather than treating mock transport as live synchronization.
- Proposed migrations and capture hooks can affect existing writes: default off, verify rollback and unchanged existing service behavior before qualification.
- Claim-after-precondition races and expired execution fences deliberately remain blocked/unknown in this correction; automatic recovery for provably never-started claimed work needs separate native qualification.

## Immutable delivery lifecycle

The outbox remains immutable ordered notification evidence. It is not a historical target to replay over newer accepted changes. `prepare` reads the current owned business record through the existing services and freezes its canonical revision and complete representable projection. The triggering cursor and delivered canonical revision are distinct: cursor2/revision2 may deliver already-merged revision3. ACK advances only cursor2 and its frozen baseline, without writing over a later canonical revision4; cursor3 can then produce a no-op.

Use the existing owner/space transaction and lease row with one bounded `active_delivery` JSONB column. Its canonical decimal version increases throughout the owner/space lifecycle and never resets between attempts or cursors. CAS verifies current version, attempt, binding and phase. Within an attempt, intent/hash, cursor, canonical revision and business/source identity never change. Before replacing a terminal slot, full intent/proof/result remains stored by value in immutable command receipts. Add only the explicit column-level runtime UPDATE permission and exact read-only readiness check; no new role, whole-table UPDATE, DELETE, credential or live migration.

States are `issued → claimed → readback-verified → acknowledged`; `issued → retired-unapplied` permits a separately prepared new attempt with a new mutationId and the same cursor. Claim and retirement race under the same row lock; retirement accepts only an exact version that has never been claimed. Retirement plus complete native observation reconciliation uses the existing business writer in one transaction. Conflicts/unsupported fields retain both evidence and a retired blocked slot; they cannot generate another delivery. Claimed/unknown attempts cannot retire or be recreated merely on timeout, not-found or lease expiry.

Every delivery write first checks the request's current live fence/permit, then looks up immutable command replay before inspecting the active slot/current head. Payload digests exclude the changing fence but bind operation, owner/space/bridge/identityEpoch, attempt and semantic input. Replaying an old result never restores a terminal slot or grants execution. A claim has a distinct immutable claimId and executionFence; the native save's fresh authorization must match the exact active claimed attempt, claim version, current fence, independent permit and original shared writer fence. Same-binding fence renewal permits metadata/result recovery, not renewed authority for an old possibly executed claim. Automatic bridge/epoch transfer remains closed even after a terminal delivery.

The Mac order is: immutable intent and stable claim request key fsync → claim/replay → complete claim receipt fsync → repeat native precondition and fresh claim/writer authorization → exclusive native-applying fsync → adapter save. Once native-applying/unknown exists, create recovery can only resolve/read back the same operation. Before claim, a changed precondition can retire a never-claimed issued attempt, atomically reconcile the observation, then independently prepare a new attempt. After claim or execution-fence expiry it stays conservatively blocked/unknown; this is not automatic recovery acceptance.

No-op updates follow the same delivery/claim lane and fresh complete readback but perform no native save. Empty create is invalid. Native proof is saved locally, then the immutable server receipt is saved locally before exact ACK; only successful readback/ACK advances baseline/cursor. All response-loss, historical replay, claim-vs-retire and original independent-field timelines require behavioral regression and independent review before source qualification.

## Reuse evidence

Existing service/repository code is the mutation authority. Apple identifier, occurrence and notification semantics follow official EventKit documentation. Transactional outbox follows the established database-transaction pattern. Better Auth device authorization and bearer documentation were checked against installed 1.7.15; broad bearer-session access is not adopted as a substitute for a scoped bridge identity. Current CLI source was inspected at fixed official releases; no tool was upgraded.
