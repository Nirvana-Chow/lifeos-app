# LifeOS 开发协作约定

2026-11-13 · LO-OPS-001 · 适用于本仓库。

本说明是 [AGENTS](../../AGENTS.md) 的项目适配说明，融合两份工程经验中的通用方法，不引入另一套规则宪法、业务需求池或公司原始材料。沿用 Superpowers + OpenSpec、现有栈和[唯一 unified-business-ui 清单](../../openspec/changes/unified-business-ui/tasks.md)。条款表达后续交付要求，不能作为现有能力、上线或本人验收证明。

## 从需求到交付

1. **先回读再认领。** 核对真实远端默认分支、Issue/PR、OpenSpec、运行证据及活跃会话、分支、worktree；按行为、根因、目标文件与验收去重。原需求保留稳定 ID、来源、验收、优先级、依赖和下一动作。新输入追加，只有本人明确取消、替代或暂停才改变旧决定。
2. **业务事实唯一。** 已实现且授权的业务 API + DB 管需求描述、用途、规划和进度，经 reviewed Skill/API 修改并独立 GET 回读；Issue/PR/OpenSpec 只映射工程计划、证据和任务。不可直接 SQL、伪造会话或改源码基线绕过 API。能力/授权缺失仅阻塞对应写入，记录待回流，不重建竞争账本。参见[既有需求工作流证据](../verification/2026-11-05-requirements-data-workflow.md)。
3. **明确负责人。** 在授权的私有协调记录中记录真实会话 ID、开发中状态与状态变更日志；不将私人会话标识发布到仓库。已有 owner 先交接或划界，同根因、同目标文件不伪拆重复轨。无服务器 claim 时采用人工调度，不能宣称自动锁。
4. **复用与计划。** 先查既有代码及原生组件能力，再查固定版本的官方文档、成熟方案和源码；仅自建已证实缺失能力。在原 Issue/计划记录来源、适用差异、选择与最小验证，不为文档改动机械外检。需求池管业务要求、OpenSpec 管规范和唯一变更清单、Issue/PR 管执行；不另引同职能规范体系。OpenSpec CLI 固定 1.16.0，自动执行设 `OPENSPEC_TELEMETRY=0 DO_NOT_TRACK=1 CI=1`。
5. **小片实现。** 先形成可审设计和验收；行为修改用适用测试观察 RED 再最小实现、验证。后续需求使用 `codex/LO-ID-description` feature 分支 + PR，commit 带真实需求 ID；不直推 main、force push、rebase 重写已有历史或 `reset --hard`。保护已有未提交、忽略文件和他人工作。小片尽早 Draft PR 跑公开 CI，等待时继续无依赖工作。
6. **验证后串行合并。** 独立技术后审，组合树整体类型检查；固定 SHA、CI run/attempt 与制品，不拼接不同分支旧绿灯。失败阻止发布并保留运行版本。通过既有私有发布路径后回读实际运行源码、相关权限和业务主流程，最后回流原需求、文档及适用归档。整项未完成不归档，归档只读。

已确认常规范围持续授权设计、实现、测试、独立评审、固定 SHA CI、常规 PR 合并与既有渠道发布读回，不逐阶段再问。保留新增范围、费用、身份/权限、真实迁移、私密外发、系统/后台设置、新渠道及不可逆操作的具体授权；只暂停受影响部分。合并、CI、部署和本人体验验收分开，保留旧证据和未完 2.1/3.1/3.2 门禁。

## 并行、运行与安全边界

- 主会话管意图、边界、优先级、复核和串行集成；子代理在隔离 worktree 做独立 slice，派发明确 branch/base、文件/接口 owner、依赖和验收。当前平台为 root + 3 子代理槽，不照搬公司白天 5 路/夜间 7 路；不为满槽开空任务。
- 同文件、Git index、业务记录/API 写入、部署均单 writer。重构建、部署、schema 操作串行；开发端口先查占用再分配，不固定照搬来源端口。重生产构建优先现有 CI 或合格隔离主机，不擅自在生产堆重负载。
- 公共 CI 只读，无生产密钥或生产部署权；私有 CD 分权。持续执行只用实际支持且已授权的机制，不把聊天承诺当后台执行。向本人简短展示完成、当前、下一步与真实阻塞。
- 沿用 closed defaults、owner 服务端隔离、受限 PostgreSQL 角色和 opt-in 集成门禁。稳定 ID/外键/约束/不可变审计承载事实，向量索引仅可重建缓存；UI/Agent 共享服务端业务规则与运行时校验。零 schema 变更优先，真实迁移须具体授权并有幂等、对账及恢复方案。
- 真实数据修改先有对象、字段、前后值和影响预览，按既有具体或持续授权执行并独立回读；不机械要求每次普通 API 写都再确认。受保护 classification 的 owner 审批仍有效，AI 提案不自我确认；数据变化须重新预览并经 CAS 或等价校验。业务 Key 不授予账户管理权，不为 HTTP/curl 验证导出凭据，不扩大 grant。
- 认证、MCP 与安全 SDK 沿已审官方实现，不手写替换或换栈。凭据、真实记录、公司原文、导出、附件、备份和私有运行配置不进 Git；synthetic 只用于隔离验证，不能在真实生产混入演示数据冒充交付。
- 工具/依赖按相关变化核官方稳定版本、变更日志、兼容性、许可、权限、回归和回退，固定版本并保留单 npm lock；不自动安装未采用工具或修改全局配置。失败保留计数：首次取证最小复现，首次修复仍失败补查同类解法，两次无实质进展停改重验，三次未解或跨组件扩散进入只读全局诊断，回答边界、链路、事实、假设、最小动作、验证六问后只做一项有证据改动。
- 不新增分钟级 AI 轮询、daemon、费用或后台设置。BuildKit/缓存先核容量、配置与恢复路径，保留 current + previous 镜像；不改容器 daemon/data-root、不删 volume 或 volume prune。规则不是清理授权；删除 symlink 不穿透目标，清理先 dry-run 定界，可恢复删除先核恢复途径，永久删除另取当次授权。

## 数据、时间与统计

- 时间点存 UTC、按业务时区展示，个人默认 `Asia/Shanghai`；纯日期保存 `YYYY-MM-DD`，不当 UTC 时间转换。服务端按业务时区算 today 并提供给 AI 卡片；纯函数接收日期/时钟。字段未传、显式空值、具体值分别处理，不用 truthy/falsy 或 `??` 混淆清空意图。
- 仅在无明确业务排序且无保存偏好时，默认 `updatedAt → createdAt → 稳定 ID` 倒序；不覆盖截止日优先等业务规则。共享统计使用同一纯函数、相同 owner 视角、过滤和口径；本人进行中集合取对应状态与本人相关集合的交集。
- 待办按截止日归期、未排期显式呈现；甘特采用真实计划起止，不用 createdAt/截止日伪造区间。优先成熟甘特/原生扩展，仅在相关需求中评估，不批量替换既有实现。
- 编号保留稳定 ID 与外部原始编号；前后端共享纯函数作预览，服务端权威重算、唯一约束兜底、冲突可操作提示并审计。不引入公司业务编号体系。
- 导入有表头映射、词表白名单和预览，保留原始状态、未知值、日期精度，不猜具体日；歧义附件留待人工。来源 Close 不等于 LifeOS 本人验收，真实导入须具体授权。导出默认北京时间至分钟命名并加碰撞保护；多 sheet/zip 按具体需求，交付前解包/读回内容，不硬套公司限流/行数阈值。

## 交互与 AI

- 复用既有 ReUI 组件、图库、语义 token、双主题和已定视觉密度；品牌色与状态色分开，适用 AA，状态同时有颜色与文字。保留[第三方声明](../../THIRD_PARTY_NOTICES.md)及 [ReUI 固定来源、版权与完整许可](../../third-party/reui/)，不照搬公司品牌。
- 桌面有效密度、稳定表列截断/尺寸、长卡限高；就地编辑可预览，删除重复入口仍保留可发现且键盘可达入口。行点击 preview、明确 detail 入口与链接直跳并存，按钮/链接/交互 cell 不被行事件吞掉；Shift 滚轮放行原生横滚，拖拽起点排除按钮等交互元素。
- group/leaf 使用稳定身份，组行不写业务叶记录；看板字段排序真实生效、详情锚点定位缺失信息，跨入口共享业务组件（含会议弹窗）。空数据、无匹配、加载、失败、未连接与降级真实表达，不填假记录。
- 约 300 行是拆分提示，不强拆 vendor 或为行数造抽象；原生动态列宽/定位等合法 style 可用，避免随手 `!important`/内联补丁。删除旧代码先证无引用，遵守组件原生 API/schema/生命周期。
- AI 产物标识 AI，未知不编；Schema 给完整枚举、词表、长度和日期精度。按需配置，明确失败降级和成本上限；经验先 review 再版本发布，不让提案直接改生效规则。

以上仅迁移通用工程方向；公司功能目录、专属编号/问题码、问题闭环工具、绩效、角色矩阵、初始密码、固定品牌/端口/阈值和砍功能清单均不自动成为 LifeOS 已具备能力、新需求或取消决定。现有需求保留原 ID 和历史条件；仅在真实需求入池并核库存/权限后采用适用机制。每天自动重建 PPT 已取消，不列待开发或待授权；按需导出不因此取消。

## 验证与文档同步

- 类型、单测、现有 lint 按影响 fail-fast（`&&` 或等价）执行，如实列失败、跳过、不可用。当前 package 无 lint 脚本，不能声称 lint 0；不为本轮规则文档安装工具。文档-only 做相对链接、口径一致性、diff 检查，不跑无意义业务测试或改 pipeline。
- API 验实际 HTTP 且不暴露凭据；UI 验真实路由、关键交互、必要手机/主题布局。源码、synthetic、浏览器、部署/恢复读回、本人体验分层记录；跳过集成测试不算通过，真实数据不可用就明确缺口。复用仍有效证据，不反复宽泛审查。
- 新输入能力同批提供适用 Agent 操作、capability discovery 和 Skill 引用；内部修改不硬造 API，只宣传已实现能力。已有 API/Skill 以各自 reviewed 合约为准，不因本说明扩大权限。
