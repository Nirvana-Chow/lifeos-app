## Behavior and reuse

The todo table toolbar offers **不分组 / 按项目 / 按领域**. It starts ungrouped. Grouping uses existing saved reference IDs, keeping separate references with the same title separate, and explicitly labels records without a reference. Each displayed todo occurs once; each group count comes from the currently supplied filtered rows. The temporary grouping choice is view-scoped and is not persisted. Existing browser-scoped column visibility/order, resizing and sorting stay available, including grouping by a hidden reference column.

The consumer extends the existing ReUI/TanStack feature set with the same native grouping feature/model already used by the requirements table. No renderer replacement, dependency, lock, API, schema, grant or classification writer was introduced. Only existing projected relationships are shown. An unavailable classification API is not bypassed or replaced by inferred factual associations.

Group rows contain a label and count only, with no completion/detail action or native editor. Edit requests reject grouped rows before resolving a real task. Leaf callbacks retain their original stable ID and revision and the existing draft/receipt bridge; post-edit navigation skips group rows. Switching grouping is disabled during an edit or blocked access. The original default seven-column performance profile and its strict oracle, preparation and 48-sample benchmark remain unchanged.

## Bounded shared-component correction

The initial actual Chrome compatibility spike exposed duplicate accessibility row indices: a group and its first leaf both announced `2` because the upstream adaptation used `row.index + 2`. The parent approved a single bounded correction in `data-grid-table.tsx`, preserving the fixed upstream source hashes, commit and license and recording the local adaptation in provenance.

The correction uses the installed TanStack 9.3.1 native `row.getDisplayIndex()`. It shares the memoized pre-pagination display order used by keyboard navigation, avoiding an added per-row/per-cell scan and avoiding page-relative virtual indexes. A retained pinned row outside the filtered keyboard order has no invented index. The virtual renderer, row-count logic, native keyboard controller and business writer are unchanged. Six real ReUI/TanStack server-rendering regressions cover grouped rows, sorting/filtering, absolute pagination, top/bottom pinning, retained out-of-filter pinning and default ungrouped behavior.
