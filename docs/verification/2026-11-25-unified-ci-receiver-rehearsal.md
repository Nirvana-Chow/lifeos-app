## 离线结果

- 坏签名、错工作流、手动运行、混用两种合同、错误 SHA、旧 run 或 attempt、缺少完整统一作业和同 ID 旧 run 对均在认领前拒绝。
- 旧 qualification 尚未就绪时保留可重试性。两条旧事件晚到、反序及并发提交后，对同一源和目标只有一次认领。更高 CI attempt 通过资格检查后也命中原认领。另一个明确选定的合成目标有自己的键。
- 子进程在合同选择提交前或提交后退出，分别读回完整的旧选择或完整的统一选择。回到精确旧源、旧模式及旧 pin 后，统一事件和已经排队但未启动的统一激活均被拒绝，之前认领的旧源不会重新认领。
- 子进程在认领提交前退出，原事件可继续认领。提交后但确认前退出，重试发现已有认领。模拟 Native 切换实际发生但完成状态未记时，独立模拟读回完成原认领。若只有 `switch_started` 标记，则保留未知并阻止重切换及合同改选，等待原 Native 确认路径。
- 7 组兼容回放及 9 组签名接收和崩溃演练。新增签名完成事件失败或取消、权威运行失败或取消、门禁作业失败或取消三种情形，均断言没有认领、没有激活。现有公开 CI 与私有回执候选保持独立。

## 实际切换与清理门禁

1. 私有 CD Root 先取得现行已安装接收器／worker 的去敏摘要及有效订阅、目标绑定和持久认领／恢复规则，和上述合同逐项对照。兼容优先的私有接收器、真实持久认领及 Native 恢复先经评审和实证。保留当前旧订阅和旧证据。
2. 核验确切 PR head、最新 main 和既有审批后，才准备一轮真实切换。在保留钉住的旧定义与现有回退的前提下，过渡版可保留旧文件并关闭旧自动触发，使生效发布入口唯一。候选里现成的两项文件删除须留待后一步，不能把这份本地分支当成获准切换 PR。首轮统一 main-push 必须获得完整同源 hosted 证据，再核私有实际同源单次认领、单次 Native 发布、实际服务 SHA/build 和 HTTPS 读回。任何未知 Native 结果继续走既有核验流程。
3. 只有一次真实迁移已成功且由独立来源读回后，才通过另外的精确变更清理休眠旧工作流。旧 Git 源、原定义摘要和旧证据继续作为回退依据。实际应用回退走获授权的固定旧源重建，核对锁定依赖、必要私有覆盖、Native 和 HTTPS，现成宿主镜像不是长期回退的必需条件。真实旧源重建本轮未验，未做清理。

候选每次正式 `main` 推送运行一套发布检查。同批变更先在集成分支收齐，再通过一次主干合并产生最终 SHA。合并前只跑定向检查。合并后核对 Actions 的同 SHA/run/attempt、门禁结论和命名证据，再核私有发布及独立 HTTPS 读回。

## 日常发布制品交接

日常 GitHub 运行提供源码资格。命中 UI 时额外执行源码浏览器夹具，门禁核对其同次证据并要求公共构建步骤跳过。全量资格中的公共镜像和编译件用于合成安全、恢复和浏览器测试。它们没有正式部署所需的已核准私有覆层。

私有发布端核验签名事件及权威 Actions 记录，按目标和 SHA 持久认领。每个获准的日常发布使用现有构建端将固定源与已批准覆层构建一次，或者查到绑定相同 SHA、run、attempt 和覆层摘要的生产镜像后复用。切换按不可变镜像 digest 执行，健康检查和 HTTPS 冒烟回读同一版本。旧结果、错覆层、可变 tag 或未知切换停在核验阶段。演练新增新建一次、已有镜像零构建、错绑定零切换和重复事件零认领的夹具，实际生产构建、复用和切换行为仍待部署管理员出具证据。

GitHub 仓库 webhook 元数据读取返回 `403 Resource not accessible by integration`。最小补件可以由现有部署管理员通过已授权渠道提供，包含脱敏的 `workflow_run` 订阅及启用状态、生产接收器和 worker 实际 pin、目标绑定以及独立签名校验的结果。需要同时确认生产认领与中断恢复的实现，以及固定源的回退演练。上次已授权主机读取回执遇到 `EACCES`，目前只有隔离重建及演练证据。已核对的公开工作流 ID 无法单独证明生产订阅或真实发布。
