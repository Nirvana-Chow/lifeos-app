# Personal health first-version leaf

Scope: LO-HEALTH-001 / Issue15, personal-agent-foundation6.3; base `f0fb029506c9c3857a26763854b04b21070b5a38`. This is a leaf source contribution for root integration. It does not complete the original health-source, API, persistence, publication or owner-acceptance gates.

## Interface and reuse

- `src/personal-health/domain.ts`: `HealthPersonal` / `HealthPersonalFields`, `validateHealthPersonal`, `normalizeHealthPersonalFields`, `validateHealthInstant`, `dateInHealthZone`, `sleepElapsedMinutes`. Complete `{title,text,occurredOn,personal}` records use the existing PersonalService path when root integrates them. Body, sleep and training reuse the frozen reviewed owner-health source semantics; no synthetic record endpoint or private Git history is transferred.
- Body retains weight `kg|lb`, body-fat percentage and six circumference sites `cm|in`. Sleep separates actual asleep minutes from its elapsed interval. Training retains original `km|mi`, duration and explicit `planned|completed`; unknowns remain `null`. Real calendar dates, explicit timestamp offsets, DST consistency and local-date consistency reuse the existing calendar validator. Only `source.kind:'manual'` is accepted. No Apple Health/Xunji connection or import is claimed.
- `presentation.ts`: `emptyHealthFields(kind,timeZone)`, `healthSummary`, labels. New training defaults to a plan to avoid inferring completed activity. No date, measurement or completed activity is fabricated.
- `fields.tsx`: `HealthFields({value:HealthPersonal,onChange,disabled?,lockKind?})`. Root retains title/text/occurredOn in its complete editor; use `lockKind:true` to preserve the category when editing an existing record. All source labels remain qualified as manual. Existing body/keyboard/touch/theme conventions are inherited from semantic tokens; there are no dependency or lock changes.
- `projection.ts`: `HealthEntry={id,revision,fields}`, `HealthMetric`, `healthMetrics`, `HealthTrend`, `projectHealthTrend(entries,metric)` (alias `buildHealthTrend`). Root must supply successfully read, owner-scoped and validated records. Each actual point retains id/revision/date/value, unit buckets never convert or merge, plans are excluded from completed metrics and unknowns are not filled with zero. Counters describe only supplied records, not source coverage.
- `summary.tsx`: `HealthRecordSummary({value:HealthPersonalFields})`, `HealthEntriesSummary({entries})`; `trend.tsx`: `HealthTrendView({trend})`. Empty input shows an honest empty state. Trends use existing ECharts6.1.0 on-demand scatter/SVG modules with theme cleanup, ARIA and an expandable actual-value table. Date labels use day-level minimum intervals and overlap handling for narrow screens.
- The frozen health schema has no project/domain/topic relation fields. This slice does not invent them or advertise reference validation it does not implement.

Native-component basis: [React controlled inputs](https://react.dev/reference/react-dom/components/input), [ECharts modular imports](https://echarts.apache.org/handbook/en/basics/import/), [ECharts ARIA](https://echarts.apache.org/handbook/en/best-practices/aria/) and the existing calendar/owner-health implementations. Local registry readback was React19.3.1 / ECharts6.1.0; existing React19.3.0 / ECharts6.1.0 remain pinned because dependency changes belong to root review. No packages were installed. The existing lock was compared before borrowing the coordinator's `node_modules` through an uncommitted symlink.

It does not test identity, API, persistent storage, production or real records.
