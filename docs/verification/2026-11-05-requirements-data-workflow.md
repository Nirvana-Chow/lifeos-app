# Requirement business workflow metadata

Scope: LO-REQ-001/#30 and LO-AGENT-001/#35; owner addition recorded in intake commit6480c2c before implementation. Base679c61d; root serializes integration and generated Skill artifacts. This slice does not edit real records or grant API access.

Design: extend existing schema2 requirement fields/metadata with optional `workflow: {state, purpose, nextStep} | null`. The original six fields remain required. State is `planned`, `in_progress`, `blocked`, `awaiting_review` or `done`; purpose/nextStep are literal owner strings up to4096 characters each, including empty strings. Omitted workflow preserves existing metadata on PATCH; explicit null clears it. Legacy records and retained commands keep their shape. Reuse the original owner-space-ID identity, binding digest, CAS, receipt, history and source validation. Workflow is separate from immutable implementation/evidence/deployment/owner-acceptance metadata.

Alternatives: editing public baseline or adding another record/table would require releases for routine changes or duplicate the existing writer; neither fits. Native JSONB storage already stores the validated typed metadata. [PostgreSQL JSON documentation](https://www.postgresql.org/docs/current/datatype-json.html) supports the existing representation. Omission/preservation and explicit-null semantics follow the convention in [RFC7396](https://www.rfc-editor.org/rfc/rfc7396); this API still requires the six existing fields and does not claim the merge-patch media type.
