## Root cause and chosen projection

The former `fields: record<string, unknown>` discovery did not reveal the native contract. A schema-only client could not construct finance's nine required fields or any complete generic-record update. The regression was first observed red: missing `lifeos_call` operation/arguments association, missing finance variants, and missing record metadata properties. The same cases now use the official in-memory MCP client and real native Agent HTTP handler with synthetic MemoryPort storage.

`field-schemas.ts` is a discovery-only structural adapter over the existing contracts: `platform/domain.ts`, `personal-candidate/business.ts` and planning, `personal-health/domain.ts`, `personal-people/model.ts`, `calendar-candidate/{domain,personal-domain}.ts`, `requirements-candidate/domain.ts`, feedback and classification contracts. It advertises field names, required/optional/null values, bounds, units, enums, discriminated alternatives, exact reference pins, dates, complete PATCH fields, revision CAS, baseline binding and same-key/body retry semantics. `schemas.ts` retains the original strict outer envelope and calls the same native validators/normalizers for actual execution; no normalization or persistence is duplicated in this adapter. Cross-field/date/DST/current-owner-pin/business checks remain native authority and are described explicitly; this does not claim JSON Schema alone can prove them. Omitted optional todo/project planning and requirement workflow fields preserve saved values; explicit null clears them.

Finance publishes five mutually exclusive kinds, each with all nine required fields. Amounts remain positive integer CNY minor units (fen). Refund requires an existing original-entry UUID, other kinds require null; transfer/repayment require distinct two-ended account references. Generic records expose complete four-field bodies and their journal/calendar/health/person metadata. Organization route type is paired with matching personal metadata. Requirements retain public LO IDs, first-edit revision zero, private UUIDs and baseline bindings. Classification exposes complete before/after/source-pin structures without adding owner approval authority.

`lifeos_discover` carries these structures; `tools/list` now also publishes a native `oneOf` associating each current operation ID with its actual argument schema. Both still use only the fresh authorized catalog. The unchanged fixed client route whitelist excludes media/career/portfolio; no new permissions, operation implementations, paths, remote loaders or grants are introduced. The existing default-closed executable remains unchanged.
