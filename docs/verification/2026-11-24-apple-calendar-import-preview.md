# Apple 日历单向导入预演（待验收）

沿用 LO-SCHEDULE-001 / Issue #12 和现有 [OpenSpec 任务](../../openspec/changes/personal-agent-foundation/tasks.md) 4.1、6.2 的验收边界。此次仅验证来源身份与预演，两个任务仍然开放。

## 合成原型

- `src/calendar-candidate/apple-import-preview.ts` 提供纯函数 `previewAppleCalendarImport(scope, snapshots, previous?)`。输入是明确指定的两个不同账户/日历组合、各自的身份代次、相同覆盖范围下的一份完整快照，以及可选的上一次成功预演状态。覆盖标记由合成测试提供，实际采集时须独立验证完整性。
- 许可源仅输出待审的新增和更新（更新带前后值）。默认合成场景要求两份快照，自动叠加源只形成展示投影。首批仅获准读取许可源时，明确传入 `overlayRead: 'exclude'`，叠加源只填 `accountId` 和 `calendarId`。这时只提交许可源快照，结果显示 `excluded-unread`（整源排除，条数未读）；误传叠加源快照时整批阻断，连空快照也拒绝。切换读取策略须重新审阅范围，上一策略的预演状态不可复用。
- 空日历和缺失快照有不同含义。重复预演使用同范围上一次成功状态，同值产生零新增、零更新。改期使用同一键替换当前投影。
- 身份键保留 Apple 账户、日历、系列 UID 和原发生标识。重复事件使用原全天日期或规范 UTC 时刻，脱离系列的改期事件沿用原发生标识。单次事件以明确的 UID 和单次标识为键。标题和当前安排只用于比较内容。全天采用 `YYYY-MM-DD`，结束日期不含当日，显示时原日期不随时区改变。
- 缺少原发生证据、重复键、源项目 ID 换绑、身份代次改变、未经确认的覆盖范围及旧键缺失都会阻断整批，保留上一份预演结果。跨日历搬迁、删除、取消、旧事件移出覆盖范围都需要对账，不能当成自动删除。只要旧身份仍存在，完全独立的新身份会被视为新事件，真实采集必须先独立验证身份连续性。
- 预演只核对标题和安排。`/personal/schedule` 的「Apple 日历预演」通过同源只读请求检查连接，当前没有运行时 Apple 读取器，因此显示「未连接」。站内日历原入口继续使用现有权限和保存路径。所有合成日历只存在于隔离测试。
- 将来只有经验证的读取器绑定当前本人空间、返回已授权且可读的普通日历，才显示选择器。自动叠加不在选择器中、不发起读取，误传额外来源时整批停止。选定日期窗口和时区后，服务端在读取前后核对身份与授权。没有已核实的对账基线时，预演只列已核对的来源行，拟新增或更新仍未知。该入口没有采集配置、数据持久化、Agent 注册或 Apple 写回能力。

在仓库根目录使用 Node 24 运行合成验证。

```sh
node --test test/apple-calendar-import-preview.test.ts
```

叠加排除的回归用例覆盖只交许可源、误传叠加源、误传空叠加快照、跨读取策略复用状态，以及原双快照合同。只将叠加快照改为可选时，误传数据仍会进入投影，该用例会失败。

## 真正导入前的条件

1. **明确所有者授权和范围。** 确定 Apple 账户及具体日历、许可来源与只读叠加来源、LifeOS 目标 owner/space、日期边界与时区、字段白名单、保留与撤销方式。读取和实际应用分别按授权执行。首批仅纳入经核准的字段，排除参与者、地点、备注、链接及附件，除非另外纳入范围。Apple 侧保持单向只读。
2. **用有授权的来源样本证明身份和范围。** 先在专用测试账户验证系列分离、夏令时、全天和默认时区、跨日历搬迁、重同步后 ID、空源及部分读取。EventKit 的原发生日期可随脱离事件保留，但浮动事件按默认时区返回。其事件 ID 在跨日历时可能变化，本地日历项目 ID 会在完整同步后丢失。实际适配器须证明账户、日历、系列及原发生标识的来源，不能直接把可变 ID 当永久键。身份或覆盖有疑问时冻结预演，保留原始证据，待审定可信映射或按新范围重新预演。取消、删除、超出范围及复发规则编辑需要各自的已审处理规则。[Apple 原发生日期](https://developer.apple.com/documentation/eventkit/ekevent/occurrencedate) · [事件 ID](https://developer.apple.com/documentation/eventkit/ekevent/eventidentifier) · [本地项目 ID](https://developer.apple.com/documentation/eventkit/ekcalendaritem/calendaritemidentifier)
3. **审阅固定批次和独立的写入边界。** 绑定不可变来源包、窗口、映射版本、目标 owner/space、内容摘要和本次命令，审阅前后值、数量、冲突及叠加范围。有任何变化时重新预演。实际写入应经原有身份和权限门禁及独立的来源证据、唯一约束、CAS、事务和收据审阅，并随新增能力交付适用的 API、发现与 Skill。手工入口仍只接受其站内来源。
4. **先证明恢复，再应用小批次。** 在独立可丢弃环境恢复受保护的包、LifeOS 数据/映射、检查点和收据，验证逐条回读及只回退本次导入且保留后续用户编辑。实际应用后用独立读路径核对身份、日期、修订和收据，再推进检查点。结果未知时暂停，按同一批次和命令查询收据、核对目标，禁止用新命令盲重试。任何回退仅作用于已有证据的 LifeOS 导入记录和叠加投影，Apple 原件保留。
