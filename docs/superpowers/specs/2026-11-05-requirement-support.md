# LO-REQ-001 / LO-VERSION-001 support slice

Continue existing unified-business-ui1.2/3.1/3.2 and the existing34 public stable requirements. Root owns canonical requirement/OpenSpec status and production. This slice does not mark source, CI, deployment or owner acceptance as interchangeable.

The minimum delivery has three owner/MFA-gated destinations: `/personal/requirements/roadmap`, `/personal/requirements/feedback`, `/personal/requirements/updates`. Roadmap uses the same public phases plus the actual private requirements snapshot. Feedback retains original long text and source, remains unapproved Inbox until explicit owner link/convert/archive, and preserves bidirectional discoverable relations. Updates combines source-backed change records with actual running source/build evidence; per-owner/space/version read state is persistent and is never acceptance.

Reuse the existing restricted Inbox JSONB writer, immutable source, owner transactions, ordered identity locks, revisions, command receipts and readback. Add a discriminated `requirementSupport` Inbox value for feedback and release-read preferences; existing personal allowedTypes and owner SQL/ACL stay unchanged. One independent owner flag `LIFEOS_PERSONAL_REQUIREMENT_SUPPORT=requirement-support-v1` defaults closed and requires the existing requirements module. Feedback/release-read records are not generic tasks, requirements or fixture rows. Never create fake data or use localStorage as the business authority.

Feedback conversion creates one private requirement and changes feedback state in the same transaction/receipt. It copies only explicitly reviewed fields; original feedback remains immutable. Linking requires exact current owner/source/revision/baseline pins. Reverse feedback lookup derives from the same stored links instead of rewriting public evidence/acceptance. Archived text/links/history remain available; delete/restore are not advertised in this slice.

New Agent feedback capabilities need independent explicit feedback scopes; existing requirements keys must not gain feedback raw-text access. Agent/default issuer/readiness remain closed unless their explicit source/native activation is verified. If a new scope producer migration is required, deliver a proposed numbered SQL and fixed prerequisites/verification/rollback list only; no live grants, SQL, credentials or real records are touched here.

New components use existing PersonalPage/ReUI/tokens and their own small layout module. Existing requirements page/views/detail/style, task, Gantt and theme files remain with the UI/root writers; only fixed destination links and the isolated update-notice hook are handed over for integration. No new framework, dependency or lock file.

Verification targets immutable original text, owner/space isolation, corrupt/overflow fail-closed snapshots, CAS/concurrent conversion, exact idempotent lost-response recovery, atomic failure, current target pins, same-origin/MFA/writable rechecks, source/runtime evidence separation, durable version-read isolation and disabled-module behavior. Native database and rendered evidence are reported separately; source-only tests do not imply those executed.
