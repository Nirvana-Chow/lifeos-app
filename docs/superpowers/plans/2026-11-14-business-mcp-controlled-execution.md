# LifeOS 业务 MCP 与受控多设备执行

2026-11-14。沿用 LO-REQ-001/#30、LO-AGENT-001/#35、LO-OPS-001/#30、LO-FILES-001/#16、LO-DATA-001/#10、LO-BACKUP-001/#20；需求和进度唯一事实源仍是已授权业务 API/DB。本计划只维护工程合同与证据映射，不是第二份需求池。

## 已确认范围与优先顺序

正常收口在途工作，登记原主 Goal、手动任务和子代理容量；随后优先可用的 ChatGPT HTTPS 业务 MCP，并接续 LifeOS 工单与多设备 Codex。此次明确授权覆盖此前“不新增执行器/自动派单”的绝对限制。保留原工单、统一集成/验收、既有 UI/字体/登录及所有未完成项，不重复派发同一个宽泛目标。

受控接单是普通程序的调度、心跳、重试和状态同步；没有明确批准且依赖满足的任务时等待，不调用模型空转。原个人业务 Agent 的 LangGraph/模型循环候选不成为工程接单的前置条件，也不增加第二个宽泛目标调度者。业务 MCP 不直接获得任意终端或生产部署能力；工程执行使用独立受限身份和操作合同。

## 库存与设计选择

- 复用已有 `src/mcp-http`、Agent API、owner/MFA、业务服务、版本/CAS/幂等回执及独立回读。先建立封闭业务 operation ID 允许集，不能依据共用 scope 或 policyClass 自动接入工程操作。官方 OAuth 采用现有认证生态，先固定版本、兼容性和事务授权合同，不手写 OAuth 或把 JWT 当原 API Key。
- 复用 `src/requirement-events` 的 projection/admission/lease/fence、`src/worker-host-candidate` 和 `src/worker-host-adoption` 的既有合同，先核当前激活与资格缺口，不因源码存在就声称已接通。工单 ready 只能来自明确准入；普通保存、进度回报和通知回执不能重复派单。
- Mac、服务器 Codex、Codex Cloud 分别验证 start/resume/status/cancel/result；dot 是实测后可接入的候选。任务根据仓库、依赖、网络、测试条件和容量选设备；只有 Apple 本机接口或本地资料工作绑定设备。不假设所有后台日志都能打开成原生 Codex 对话。
- 临时文件按用途选择已授权、隐私合适的附件或私有暂存路径，不强制永久存服务器。新增文件输入必须适配官方顶层 file 参数、精确权限和受限下载；不扩大 MCP JSON 限制搬 Base64，不把 sandbox 路径、页面或临时 URL 当原件已持久化。

| 边界 | 合同 |
| --- | --- |
| 需求内容 | 稳定 requirement ID、source/content version、当前内容与变更事件；业务 API/DB 权威，工程资料链接原 ID |
| 执行记录 | task/subtask ID、内容版本、设备、原生会话/云任务 ID、workspace、branch、状态、阶段、证据；重试/换设备新记录保留前次 |
| 领取与容量 | 单有效执行者、generation/fence、设备任务/子代理/重构建测试槽/全局模型预算；现 Goal/手动任务计入或预留，观测缺口明示 |
| 需求送达 | 已保存、待送达、待确认、已采纳分开；记录 adopted content version，默认通知原 owner，不派重复任务 |
| 文件交接 | file ID、工单、bytes、checksum、retention、持久化回执、独立下载及领取 ack；唯一原件和长期证据保护 |
| 同步与迁移 | 原 authority、稳定来源/原 ID、正文/时间/来源版本、增量 checkpoint、去重/冲突/删除语义、失败/截至时间 |
| 集成与发布 | 共享 Git index、端口/DB/schema、重构建与环境发布单 writer；固定 commit/制品，失败保留旧运行版 |

Root 直接划分独立实现 worktree/clone 与文件/接口 owner，不让子代理继续派生。worktree 不代替任务锁。工程 token 不授予业务 owner 审批、任意 shell 输入或部署权；现审批和生产信任继续在原边界执行。

## 分片实施与准入

1. **接续与登记**：记录现有 Goal/执行、原需求内容版本和当前容量，保护所有 worktree/分支/未知命令。新增调度不得自动领取原 Goal；没有可观测执行标识的占用按保留处理。
2. **业务 MCP**：封闭允许集 → 官方 OAuth/owner-MFA continuation → token/consent/原 grant 的当前授权及事务 fence → HTTPS/安装/网页与手机 CRUD/搜索和独立回读。测试记录隔离或不可执行，不能为验业务 MCP 调用 claim/启动开发。
3. **受控执行适配**：先各设备能力探针，再批准的不同小任务；任务准入绑定内容和依赖。普通程序维持心跳、阶段事件、有限重试，执行模型只在有效工作开始时运行。所有配置绑定已有授权资源和固定代码，不自动新增付费/额度。
4. **断网和改单**：失联停止新派发；lease 过期只进入待核，不推定旧进程结束。核对旧进程/成果并安全撤销资格后才重派，失权者不得正式回写/合并/发布。重连补传对账，支持 pause/drain/cancel；安全检查点确认内容变化，交付前未采纳变更阻止按旧标准完成。
5. **文件和数据**：真实新生成 ChatGPT 文件 → MCP → 持久化 → 网站/Codex分别下载核验。授权旧 LifeOS 日记/项目/知识及专业源先盘点、独立备份/恢复、小样本映射，再幂等连续分批导入与同步；不删除独有证据，不扩大到公司正文或整个照片库。结构化查询/全文检索先交付，RAG 是后续可重建增强。

## 开发环境与真实验收

功能代码必须在实际合格开发环境完成适用 tests/types 和完整 production webpack build、同产物默认关闭检查，再进入正常 PR/CI/CD。开发环境可以是 Mac、隔离服务器或云工作区；资源不足换合格环境，不跳过。重构建排队；相同源码/依赖/环境证据可复用，变化后重验。文档-only 做对应检查。固定 main 原 CI、私有自动发布、Native + HTTPS 独立读回与本人体验仍分开取证。

| 验收 | 必须有的证据 |
| --- | --- |
| 业务接通 | ChatGPT 实际 OAuth/插件安装、网页和真手机查询/保存/同 ID 更新/独立 GET、Mac 离线仍可保存 |
| 工程执行 | 两处合格环境领取不同已批准任务，真实执行 ID、工作区/分支、阶段/阻塞/结束回传；单任务竞争只一有效者 |
| 资源与网络 | 现 Goal/手动占用和真实容量上限；断网停新任务、旧进程待核、失权 fence、重连对账零重复；pause/drain/cancel |
| 执行中变更 | 四种送达状态、采纳版本、安全检查点调整、未处理变化无法按旧标准完成，通知 ack 不派新单 |
| 文件 | 当场新生成真实文件、官方参数、持久化 receipt、网站及 Codex独立下载 SHA/bytes/ack、过期与 unknown 恢复 |
| 数据与恢复 | 原文/ID/版本/关联对账、重复迁移零重复、专业 authority 不双主写、独立于业务服务器的备份真实恢复 |
| 工程交付 | 开发环境固定代码 tests/types/full build 记录、PR/main 固定 CI/制品、原发布读回和失败保旧版 |

实现、部署、接通、验证和本人体验分别报告。某平台能力缺失只阻塞该适配；先完成独立工作，待登录/新权限/缺文件/新费用具体可审时给本人一份完整简短操作。此计划和合成测试均不代表上述真实验收已通过。
